# Снятие косметики у других игроков — обе версии

## Что удалось установить

30 октября 2026 в 16:51 МСК рабочий API возвращал пустые комплекты (`{}`) и для
MrZakon (1.21.11), и для MrDanuul (26.1.2). В сохранённых конфигурациях обоих
профилей косметика также была выключена. Значит, снятие дошло до сайта.

При этом старые установленные сборки продолжали записывать таймауты в журнал.
Их контрольные суммы соответствовали сборкам до исправления таймаута:

- 1.21.11: `c136c6c09d6091ce3e1f8494742d6e56f80b781be6fa149e93db6111134d96d5`;
- 26.1.2: `ca07adb51bbcdd811c8bf3a71a4463fa10e5e915f311dfad1249876135ad80f0`.

Диагностическое чтение API через новые соединения Java 21 и 25 завершилось
HTTP 200 за 0,6–1,8 секунды. Оба предложенных протокола фактически согласовали
HTTP/1.1. Наблюдение указывает на проблему долгоживущих соединений/таймаутов;
точное внутреннее состояние сокетов запущенных Minecraft не снималось.

## Исправления

- Публичный список использует отдельный HTTP-клиент. Сохранение комплекта,
  вход и heartbeat не используют его пул соединений.
- Используется HTTP/1.1, который согласовал действующий сервер при диагностике.
- При ошибке ввода-вывода, в том числе таймауте, старый HTTP-клиент выводится
  из использования. GET однократно повторяется через новое соединение.
  POST автоматически не повторяется: сервер мог уже применить изменение.
- Интервал опроса чужих комплектов сокращён до одной секунды плюс длительность
  запроса. Сетевой обмен остаётся фоновым.
- Полученный пустой комплект заменяет прежний целиком и снимает все категории.
- Если свежего списка нет 10 секунд, чужая косметика скрывается. Иконка
  присутствия сохраняет прежний отдельный TTL 45 секунд. Возврат достоверного
  списка восстанавливает актуальную экипировку. При долгом обрыве связи это
  может временно скрыть косметику, которая всё ещё надета.
- Во время отправки изменения статус показывает «Сайт: сохранение…».

## Сборка и ограничения

Обе версии собираются через `assemble -x test -x compileTestJava --offline --no-daemon`.
Автоматические тесты и запуск Minecraft не выполнялись. Диагностика ограничилась
чтением файлов и публичного API. В установленных профилях JAR не заменялись.

Исправления находятся в новых сборках; уже работающий JVM не получает новый
код после изменения исходников или JAR в папке проекта. Взаимное отображение
после установки новых файлов в этой работе визуально не подтверждено.
