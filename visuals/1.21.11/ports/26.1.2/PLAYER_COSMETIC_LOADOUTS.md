# Независимая косметика персонажей Minecraft

## Причина

Чтение рабочего API подтвердило, что MrZakon (1.21.11) и MrDanuul (26.1.2)
используют один аккаунт сайта. Оба получали общий плащ 101. Раньше сервер
хранил комплект на аккаунт сайта и рассылал изменение всем его активным UUID.
Это меняло и локальный выбор второй игры через последующее чтение профиля.

## Хранение и API

- Отдельный комплект хранится в `project_records`, коллекция
  `minecraft_cosmetics`, ключ `[ID аккаунта сайта, UUID Minecraft]`.
  Новая SQL-таблица и изменение схемы MySQL не требуются.
- Существующий общий комплект остаётся шаблоном для первого подключения
  нового персонажа. При heartbeat он копируется в независимую запись UUID.
  У уже созданных персонажей изменение шаблона ничего не переодевает.
- Сохранение меняет одну запись персонажа. Ревизия, проверка конфликта и
  условный UPDATE по предыдущему содержимому относятся только к этому UUID.
  Пустой комплект — сохранённое снятие, а не повод снова подставить шаблон.
- Уведомление обновляет presence только нужного UUID текущего аккаунта сайта.
  Публичный список других игроков и их отрисовка продолжают работать.
- Аутентифицированный GET/POST `/api/client/cosmetics/equipped` принимает UUID
  (GET — query, POST — JSON). В ответе возвращается этот же UUID.
- Старый мод без UUID больше не может записать общий комплект этим маршрутом.
  Клиент не переходит на общий API при отсутствии нового ответа: он показывает
  необходимость обновить API. Требуется обновить оба JAR.
- Авторизация, проверка ID каталога, состояние раздела и ограничение запросов
  сохраняются. Чтение другого аккаунта сайта по известному UUID не открывается:
  ключ всегда включает ID текущего авторизованного аккаунта.

## Мод и сайт

- Каждая версия передаёт UUID текущего игрока в чтении и сохранении комплекта.
  До подключения персонажа общий комплект в настройки игры не применяется.
- При смене UUID сбрасывается исходная ревизия и отменяется старое чтение.
  Ответ и отложенное применение от другого персонажа игнорируются.
- На сайте добавлен выбор персонажа по имени и UUID. Сохранение и обновление
  кнопок относятся к выбранному персонажу. Отдельно подписан шаблон для новых
  игроков. Выбор персонажа запоминается в браузере.
- `/api/client/cosmetics/players` возвращает только персонажей текущего аккаунта.
- Одинаковый UUID в разных версиях означает одного персонажа и один комплект;
  разные UUID получают независимые комплекты.

## Сборка и границы проверки

Обе версии собраны через `assemble -x test -x compileTestJava --offline --no-daemon`.
JavaScript проверен на синтаксис. Автоматические тесты, пробные переодевания
рабочих персонажей и запуск Minecraft не выполнялись. JAR в игровых `mods`
не заменялись. Для применения клиентской части нужно обновить оба экземпляра.
